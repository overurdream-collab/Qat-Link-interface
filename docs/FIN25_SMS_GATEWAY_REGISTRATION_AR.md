# FIN25 — تسجيل Samsung SMS Gateway

## الحالة
تم إعداد مخطط قاعدة البيانات فقط. **لم يتم إدخال مفتاح الجهاز الفعلي، ولا تفعيل الجهاز أو إثبات التوقيع.**

بعد تطبيق الترحيلات 001–007 على قاعدة اختبار، نفّذ 008 مرة واحدة بصلاحية مالك قاعدة البيانات. يحتوي الجدول على معرف الجهاز، مفتاحه العام بصيغة PEM/SPKI، بصمة SHA-256، حالة الاعتماد، وسجل آخر اتصال. جدول nonces لمنع إعادة استخدام الطلبات الموقعة.

## بروتوكول التسجيل الآمن (قبل تنفيذ API)
1. يعرض Android Gateway المفتاح **العام** فقط، ومعرف الجهاز وبصمته. يبقى المفتاح الخاص داخل Android Keystore.
2. يضيف المشرف المفتاح العام إلى قاعدة البيانات بحالة `pending` عبر مسار إداري موثوق، لا عبر API عامة تسمح بالتسجيل الذاتي.
3. يصدر الخادم تحدياً عشوائياً محدود العمر؛ يوقعه الهاتف بالمفتاح الخاص.
4. يتحقق الخادم من التوقيع والبصمة ومعرف الجهاز ووقت الطلب وnonce غير مستخدم، ثم يسمح للمشرف بتحويل الحالة إلى `active`.
5. كل polling/heartbeat/result لاحق يجب أن يحمل توقيعاً موثقاً مع timestamp وnonce، وأن يرفض الخادم الأجهزة الموقوفة والمفاتيح الملغاة.
6. لا تعرض OTP أو تخزنه بنص صريح في سجلات الهاتف أو الخادم؛ تخزين OTP hash محدود الصلاحية في خدمة الهوية المستقلة.

**مهم:** هذا الترحيل لا يضيف API التسجيل أو التوقيع، ولا يعني جاهزية الإرسال. يلزم فحص تنسيق المفتاح والتوقيع الموجودين في تطبيق Android أولاً حتى لا نخترع بروتوكولاً غير متوافق.
