# اختبار FIN25 → Identity → FIN08 المحلي باستخدام هاتف فعلي

**الحالة:** أداة تشغيل اختبار يدوية، وليست إصدارًا عامًا أو APK تسجيل دخول. لا تفتح OTP/Identity عبر شبكة عامة.

## الشروط
- FIN25 Docker: `fin25-test-db` متاحة، `fin25-test-otp-1` متاح؛ عامل Android المعتمد `active` و`ONLINE`.
- Identity المحلية تعمل على `127.0.0.1:8090`، ومتّصلة مسبقًا بـFIN25 وFIN08.
- Node.js 22+ وDocker CLI على جهاز Windows المستخدم للتشغيل.
- هاتف استقبال تتحكم فيه وشريحة إرسال بها رصيد. رمز SMS صالح لخمس دقائق؛ **لا تستخدم طلب OTP السابق**.
- إدخال رمز OTP ورقم الهاتف في نافذة PowerShell المحلية فقط، لا في المحادثة ولا في ملفات المشروع.

## تشغيل (بعد نجاح CI)
```powershell
$p='F:\maqwati-integration-fin25-20261121'
git -C $p pull --ff-only origin integration/fin25-identity-consolidation-20261121
node --check "$p\scripts\fin25_identity_live_pilot.mjs"
node "$p\scripts\fin25_identity_live_pilot.mjs"
```

البرنامج يجري فحص صحة Identity **قبل** طلب SMS. ثم يطلب اختيار حالة الحساب:
- `existing`: تسجيل الدخول إلى حساب سبق ربطه بنفس الهاتف؛ لا ينشئ حسابًا جديدًا.
- `customer`: يتطلب موافقة صريحة داخل الأداة لإنشاء ملف عميل Identity/FIN08 جديد؛ **لا ينشئ علاقة تاجر–عميل أو يوافق على حركة مالية**.
- `merchant`: مثل السابق، مع اسم المتجر.

بعد كتابة `YES` حرفيًا، يسأل عن رقم الهاتف دون عرضه في الطرفية، ويرسل **طلب OTP واحدًا** إلى خدمة FIN25 عبر `docker exec` المحلية (لا يُعرّض مسار الطلب للعامة). أدخل الرمز المستلم خلال خمس دقائق دون طباعته. يتبادل إثبات الهاتف قصير العمر مع Identity المحلية، ويختبر JWT عبر `GET /v1/identity/me`.

## مخرجات القبول
- `HTTP 202`: جرى إنشاء الطلب فقط، ولا يثبت وصول الرسالة.
- `FIN25: code verified`: رمز OTP تحقق منه الخادم.
- `PASS: OTP verified -> Identity session -> /me; FIN08 provisioning accepted.`: صدرت جلسة Identity واجتازت `/me` في وقت الاختبار.
- عند الفشل لا يعاود إرسال SMS تلقائيًا؛ استعرض `PILOT BLOCKED` دون مشاركة رمز OTP أو المفاتيح.

## حدود الاختبار
- هذا اختبار بموافقة بشرية وفي نطاق جهاز المستخدم؛ **ليس** حلًا لحماية توجيه OTP العام، ولا بديلًا عن بوابة HTTPS موثوقة ومعدل استخدام موزع.
- لا يُثبت تلقائيًا أن شاشة Flutter/Android الإنتاجية تستطيع تسجيل الدخول؛ لا تزال `IDENTITY_API_BASE_URL` ومسار HTTPS العام يتطلبان تجهيزًا، ولا يُنشر رابط Cloudflare المؤقت في إصدار إنتاجي.
- لا تُعدّل حاوية Identity/FIN25/FIN08 العاملة ولا قواعد بياناتها أو الأسرار، ولا تدمج PR #71 قبل مراجعات الإصدار.
