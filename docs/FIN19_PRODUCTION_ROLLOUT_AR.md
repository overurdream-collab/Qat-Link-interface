# FIN19 — إجراء نشر وحماية الدفتر المعتمد

## قبل النشر
1. أوقف كتابة الحركات المالية مؤقتاً أو ضع التطبيق في وضع الصيانة.
2. أنشئ نسخة احتياطية متسقة من PostgreSQL وتحقق من إمكانية استعادتها إلى قاعدة منفصلة.
3. نفذ الترحيلات 001–005 إذا لم تكن مطبقة مسبقاً، حسب سجل ترحيلات البيئة. **لا تعِد تطبيق ترحيلات غير قابلة للتكرار.**
4. استخدم حساب ترحيلات مخصصاً يملك DDL، ولا تستخدم حساب التطبيق.

## تطبيق الحماية
نفذ من جهاز موثوق ومتصل بقاعدة الاختبار أولاً:

```bash
psql "$DATABASE_URL" -X -v ON_ERROR_STOP=1 -f server/sql/006_fin19_approved_movement_integrity.sql
```

يُجري الترحيل فحصاً للقيود القديمة داخل معاملة واحدة. إذا وُجدت مخالفات فإنه يفشل ويُلغى كله؛ لا تتجاوز هذا الفشل ولا تعدل القيود المعتمدة مباشرة.

## التحقق من وجود الحماية
```sql
SELECT tgname, tgrelid::regclass AS table_name, tgenabled
FROM pg_trigger
WHERE NOT tgisinternal AND tgname LIKE 'fin19_%'
ORDER BY tgname;
```

يجب أن تظهر خمسة triggers مفعّلة: حماية INSERT للدفتر، وأربعة لحماية مصادر القيود.

## صلاحيات التشغيل
تحقق من أن مستخدم التطبيق **ليس مالكاً** للجداول أو وظائف الحماية، ولا يحمل صلاحيات SUPERUSER أو BYPASSRLS أو CREATE على مخطط الإنتاج، ولا يستطيع تعطيل المشغلات أو تعديل بنيتها. لا تمنح TRUNCATE للجداول المالية. يجب اختبار ذلك بحساب التطبيق نفسه لا بحساب الترحيل.

## اختبار بعد النشر
- أعد تشغيل اختبارات تكامل الخادم في بيئة منعزلة.
- اختبر إدراج دين معتمد صحيح ورفض إدراج مبلغ/عملة/علاقة مزورة.
- تحقق من أن الحركات المعلقة والمرفوضة لا تؤثر على الرصيد، وأن العملات لا تُجمع.
- تحقق من النسخ الاحتياطي والاستعادة، ومن أثر الترحيل على زمن القفل.
- راقب سجلات الأخطاء والتعارضات قبل إعادة السماح بالكتابة.
