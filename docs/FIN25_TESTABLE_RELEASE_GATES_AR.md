# FIN25 — شروط تسليم نسخة OTP قابلة للاختبار

## الوضع الحالي
- Android: هوية RSA داخل Android Keystore، إثبات challenge، شاشة إثبات، عامل foreground، وHeartbeat.
- Backend: تسجيل جهاز بإذن مسؤول، challenge صالح لدقيقتين، إثبات مرة واحدة، موافقة إدارية منفصلة، heartbeat موقّع مع منع nonce مكرر.
- خدمة FIN25 تعمل منفصلة على 127.0.0.1:8082 ولا تشكل بحد ذاتها تكاملاً مع خدمة OTP أو JWT.
- **إرسال SMS معطل عمداً في فرع Samsung** حتى لا يعاد إرسال رسالة بسبب انتهاء lease أو تعارض الطابور.
- لا يجوز تطبيق مخطط 009 على قاعدة الإنتاج قبل تجربة ترحيل معزولة وتدقيق توافق 007/008.

## خطوات بيئة اختبار منفصلة
1. استخدم PostgreSQL مؤقتة لا تحتوي بيانات مستخدمين؛ طبّق `server/sql/009_fin25_gateway_isolated.sql`.
2. عيّن `DATABASE_URL` و`FIN25_ADMIN_KEY` عشوائياً (32 حرفاً على الأقل)، وشغّل `node server/src/fin25_gateway_enrollment.mjs` من جذر المشروع بعد تثبيت حزم server.
3. ضع HTTPS reverse proxy موثوقاً أمام الخدمة؛ لا تكشف المنفذ 8082 مباشرة للإنترنت.
4. في Samsung أنشئ المفتاح وانسخ deviceId وPEM للمسؤول عبر قناة موثوقة.
5. يسجل المسؤول الجهاز عبر `POST /v1/gateway/enroll` مع ترويسة `X-FIN25-ADMIN-KEY`، وJSON `{"deviceId":"...","publicKeyPem":"..."}`.
6. أدخل عنوان HTTPS في Samsung واضغط إثبات المفتاح؛ يصبح الجهاز proved فقط.
7. يوافق المسؤول عبر `POST /v1/gateway/approve` مع المفتاح الإداري و`{"deviceId":"..."}`.
8. شغّل اختبار Heartbeat؛ يجب أن يعمل للجهاز active ويرفض pending/proved/revoked.
9. لا تبدأ إرسال SMS قبل اختبار الطابور المتوافق مع FIN25، منع تكرار jobId، استرداد الحالات غير المؤكدة، وOTP proof إلى مُصدر JWT الموثوق.

## معايير النجاح التي لم تُثبت بعد
- تشغيل FIN25 مع PostgreSQL مؤقتة، وتجربة التسجيل/التحدي/الإثبات/الموافقة/الإلغاء ورفض replay فعلياً.
- توحيد مسار Poll/Result وتشفير payload ومزامنة حالات OTP دون ازدواج الإرسال.
- استعادة worker بعد فقد الاتصال وإعادة التشغيل، وضبط اختيار SIM، وإثبات callback من Android.
- ربط OTP proof بخدمة هوية تصدر JWT وفق issuer/audience/RS256؛ لا تُصدر JWT داخل Gateway.
- بناء APK على آخر commit وتنزيله، ثم إرسال OTP واستقباله والتحقق منه على Samsung فعلي.
- تدقيق صلاحيات PostgreSQL، سجلات التدقيق، rate limits، الأسرار، HTTPS، وإجراء مراجعة PR قبل الدمج.

## قيود
- لا تعديل للمخططات المالية 001–008 أو قاعدة Docker المحلية.
- لا دمج إلى main ولا تفعيل إرسال حقيقي قبل تحقق البنود أعلاه وموافقة المسؤول.
