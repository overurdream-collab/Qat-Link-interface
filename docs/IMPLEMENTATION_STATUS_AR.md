## تعريف الحالات
- **مختبر محلياً في CI**: كود وWidget/Unit tests عند GitHub، ضمن بيئة اختبار Flutter.
- **واجهة أو منطق جاهز للربط**: ليس API أو خدمة إنتاجية.
- **غير متصل**: لا يوجد خادم أو حفظ أو جلسة أو تبليغ فعلي.
- **قرار مؤجل**: تحتاج موافقة المنتج ولا تُفعّل بالتخمين.

**FIN-07 (مدمج — PR #16):** مكونات إضافة جهة اتصال غير منضمة، ومطالبة معلقة في سجل التاجر، وعرض المبالغ ونسخ كشف غير معتمد موجودة في main. **لا يوجد تخزين دائم أو دعوة خادمية أو إرسال واتساب تلقائي أو ربط موافقات العميل القديمة**؛ لا تصنف الميزة جاهزة للإنتاج حتى ربط Backend. [المتطلبات](MERCHANT_PENDING_DEBTS_BEFORE_APP_AR.md).

**FIN-08 (انضمام العميل):** أضيف `JoinedCustomerClaimsQuery` و`CustomerJoinedClaimsPanel` لعرض **جميع المطالبات التاريخية** مباشرة عند تزويدهما بمطابقات حساب موثقة، مع قبول/رفض كل مطالبة مستقلة. `MerchantDebtStatusQuery` ينقل المطالبات من خارج التطبيق إلى انتظار العميل بعد التحقق فقط. **ما لم يُنفَّذ:** OTP ومطابقة البيانات الخادمية، صندوق رسائل متصل في واجهة العميل، تسليم إشعار Push، تسجيل قرارات فعلي في Backend، ترحيل `MovementModel` وفحص احتياطات عدم التكرار بين الأجهزة. المكوّنات الأولية لا تخزن السجلات بعد إغلاق التطبيق.

**عقد الاستكمال الفني للمرحلة FIN-08:** [FIN08_JOINED_CUSTOMER_BACKEND_CONTRACT_AR.md](FIN08_JOINED_CUSTOMER_BACKEND_CONTRACT_AR.md) — يتضمن واجهات API المقترحة وشروط مطابقة الهاتف ومنع تكرار الديون وقيود الخصوصية واختبارات القبول. **وجود العقد لا يعني تنفيذ Backend.**

## حدود إطلاق النسخة

لا تعلن إطلاق التطبيق للمستخدمين الحقيقيين دون:
1. إثبات مصادقة وربط جهاز/جلسة وسلطة أدوار خادمية.
2. خدمة بيانات دائمة وتزامن علاقات وموافقات وحركات وحجوزات، دون ازدواج.
3. ضمان أن سجل الديون المعتمدة لا يتغير بدون موافقة الطرف الثاني وتدقيق.
4. اختبار إغلاق الحجوزات بعد الوقت واستهداف التذكيرات وتفضيلات العميل على جهاز فعلي.
5. تجربة إرسال واستقبال وتجاهل وتأكيد حجز وفشل الشبكة وإعادة المحاولة على أكثر من جهاز.
6. مراجعة الخصوصية والأمن واختبار تعارض العملات والحدود والباقات.
