# P0 — تشغيل خدمة هوية مقوتي لينك المنفصلة (دليل استلام)
التاريخ: 19 نوفمبر 2026. **الكود حاضر في الفرع؛ لا يعني ذلك أن الخدمة نُشرت أو عملت على هاتف المستخدم.**

## البنية
- تطبيق Samsung SMS Gateway في المستودع `smsgateway` لا يتغير، ولا تدخل أسرار الهوية إلى APK البوابة.
- خادم `fin25-test` القائم ينفذ `/v1/auth/otp/request` و`/v1/auth/otp/verify` ويعيد `proofToken` صالحاً لمدة 120 ثانية؛ يستهلكه `POST /v1/internal/otp/proof` مرة واحدة بتوقيع خدمة هوية ومفتاح داخلي.
- خدمة جديدة: `server/src/identity_server.mjs` منفصلة عن خادم المالية. تستقبل `POST /v1/identity/session` بجسم `{proofToken, requestedRole?, displayName?}`؛ `requestedRole` إما `customer` أو `merchant` عند التسجيل الأول فقط. الدخول اللاحق يرسل الإثبات فقط. ترفض `supplier`.
- `GET /v1/identity/me` يتطلب `Bearer accessToken` ويطابق الدور مع قاعدة الحسابات. جلسة RS256 قصيرة العمر (15 دقيقة)، ولا يوجد refresh أو PIN مخزن بعد.
- الشاشة `IdentityAccountScreen` تعرض هوية المستخدم دون أرصدة وهمية. الدفتر الحقيقي **غير موصول**؛ لا تعلن جاهزية الإنتاج.

## إعدادات نشر الخدمة (أسماء فقط؛ لا ترفع قيماً سرية)
| متغير | المعنى |
|---|---|
| `IDENTITY_DATABASE_URL` | قاعدة PostgreSQL **منفصلة**؛ طبّق ترحيل `server/sql/008_p0_identity_accounts.sql` بمستخدم ترحيل |
| `IDENTITY_PRIVATE_KEY_PEM` | مفتاح توقيع RS256 خاص يُحفظ فقط في الخادم |
| `IDENTITY_PUBLIC_KEY_PEM` | مفتاح عام مطابق لمدقق الجلسات |
| `IDENTITY_ISSUER`, `IDENTITY_AUDIENCE` | نفس قيم `JWT_ISSUER/AUDIENCE` في FIN25 و`AUTH_ISSUER/AUDIENCE` في الخادم المالي |
| `FIN25_INTERNAL_PROOF_URL` | عنوان خدمة FIN25 **الداخلي** المنتهي بـ `/v1/internal/otp/proof`، لا النفق الخارجي |
| `FIN25_INTERNAL_API_KEY` | قيمة تطابق `OTP_INTERNAL_API_KEY` الموجودة لدى FIN25؛ لا تظهر للتطبيق |
| `IDENTITY_PORT` | اختياري 8090 |
| `IDENTITY_BIND_HOST` | افتراضياً 127.0.0.1؛ يجب ضبط شبكة الوكيل العكسي بأمان |
| `IDENTITY_PG_SSL` | استخدم true للقاعدة البعيدة مع تحقق شهادتها |

المدقق المالي يعتمد مفتاح `AUTH_PUBLIC_KEY_PEM`، وFIN25 يعتمد `JWT_PUBLIC_KEY_PEM`. جميعها **مفتاح عام من هوية واحدة**. لا تغيير في `HS256` الخاص بمشروع test4؛ غير مستخدم هنا.

## إعداد Flutter
- يبنى التطبيق مع `--dart-define=IDENTITY_API_BASE_URL=https://identity.example.test/` بعد نشر خدمة الهوية على HTTPS موثوق **فعلي**؛ لا تستخدم رابط example كما هو.
- شاشة تسجيل الدخول تعرض `الدخول برمز تحقق SMS`؛ PIN الحالي ليس مدخلاً لهذا المسار. شاشة التسجيل تمرر الدور والاسم فقط بعد تحقق الهاتف، ولا ترسل PIN.
- شاشة إعداد OTP تطلب العنوان الحالي لنفق FIN25 التجريبي، ويمكن تغييره دون بناء APK آخر، لكن **عنوان هوية الحساب يجب تثبيته وقت البناء** حتى لا يُرسل إثبات حساس إلى مضيف يختاره المهاجم.
- إذا لم يُحدد `IDENTITY_API_BASE_URL` يمنع Flutter الانتقال لتسجيل حساب ويفسّر السبب؛ لا يمنح جلسة وهمية.
- تطبيق اختبار OTP المستقل في PR #60 يبقى `enableIdentity=false` افتراضياً.
- لا تخزن `proofToken` أو accessToken في shared preferences أو logs؛ في P0 عمر الجلسة قصير ويتطلب إعادة OTP بعد إعادة فتح التطبيق.

## الترتيب التشغيلي الإلزامي قبل APK قبول حقيقي
1. تحقق read-only من صور الحاويات `fin25-test` الحالية، وتطابق مسارات الخادم والنسخ المطبقة؛ لا تسحب `fin25` الأصلية.
2. ضع خدمة الهوية وقاعدتها في شبكة اختبار مستقلة؛ طبّق SQL المخصص لها فقط بموافقة تشغيلية، وراجع least privilege.
3. ضع مفاتيح RS256 ومفتاح FIN25 الداخلي في أسرار الخادم، لا في ملفات المصدر أو رسائل المستخدم.
4. تحقق من الوصول الداخلي إلى `/v1/internal/otp/proof`، وفعالية توقيع خدمة الهوية، وارفض محاولات إعادة استخدام الإثبات وتغيير الدور.
5. افحص حماية نطاق HTTPS للهوية، ومعدل الطلبات والرقابة والتوقيت وأخطاء الشبكة؛ لا تنشر endpoint الداخلي إلى الإنترنت.
6. بعد موافقة اختبار SMS: تجربة هاتف رقم واحد، OTP صحيح/خاطئ/منتهي/مستهلك، ثم `/v1/identity/me`، ثم اختبار دخول الحساب الثاني.
7. قبل وصل الدفتر المالي: أضف provisioning الموثوق للتاجر وverified-phone للعميل إلى خادم FIN08؛ وحدّد الصلاحيات وتحديث الجلسة وإبطالها. لا تعرض شاشة AppState الوهمية في الإنتاج.

## حدود الإصدار الحالي
- خدمة الهوية مهيأة للإصدار كعملية Node مستقلة لكن **غير منشورة**.
- لا يوجد refresh/revocation token بعد، ولا حماية ربط الجهاز أو نقل الرقم، ولا provision لخادم FIN08، ولا سجلات حسابات حقيقية مثبتة.
- التوقيع وبيانات الهوية تحققت في اختبارات وحدة فقط عند ظهور نتيجة CI. لا تدّعِ اكتمال دورة دخول الحقيقية قبل تشغيل خادم الاختبار وتثبيت APK موقّع ومختبر.
- بيئة `fin25-test` وSMS Gateway تظلان على حالهما حتى موافقة تشغيلية مستقلة.
