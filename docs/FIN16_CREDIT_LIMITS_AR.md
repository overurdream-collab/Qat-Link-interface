# FIN-16 — حدود الائتمان والتنبيه بالمخاطر حسب العميل والعملة

**المرجع:** وثيقة الدفتر المحاسبي v2.2، القسم 11.  
**الحالة:** تنفيذ برمجي مستقل، يلزم اجتياز PostgreSQL وFlutter CI قبل الدمج. ليس نشرًا إنتاجيًا.

## القاعدة المالية

لكل علاقة بين التاجر والعميل ثلاثة حدود مستقلة YER وSAR وUSD؛ لا تحويل أو جمع عملات.

1. الرصيد المعتمد يُقرأ من financial_movements فقط، بما في ذلك الديون والدفعات والعكس؛ قد يكون سالبًا كرصيد دائن للعميل.
2. المخاطر المعلقة تُعرض منفصلة: ديون ودفعات merchant_claims غير المعتمدة وغير المرفوضة، وعمليات relationship_operations المعلقة. لا تعتبر أموالًا مؤكدة ولا تضاف إلى الرصيد المعتمد.
3. تاجر العلاقة وحده يُفعِّل/يعطِّل حد عملة محددة؛ العميل يرى السياسة والمخاطر دون تعديلها.
4. سياسة warn: لا تمنع تسجيل الدين الجديد، لكنها ترجع warning خادميًا إذا تجاوز الرصيد المعتمد الحالي + مبلغ الدين الجديد الحد.
5. سياسة block: ترفض **إنشاء طلب دين جديد** في العلاقة المعتمدة فقط إذا تجاوزت المعادلة السابقة الحد. لا تمنع تسجيل دفعة ولا تصحيحًا قائمًا ولا اعتماد دين كان معلقًا من قبل، حتى لا تخفي التزامات حدثت بالفعل.
6. إذا كان الرصيد المعتمد -100 YER والحد صفر، يمكن إنشاء دين جديد 50 YER طالما الرصيد المتوقع -50 YER؛ ودين جديد 101 YER ممنوع لأنه يجعل الرصيد المتوقع +1 YER.
7. سياسة المنع ليست ضمانًا لعدم تجاوز الرصيد النهائي: قد تتراكم ديون معلقة قبل اعتمادها وتتجاوز عند الموافقة. يعرض النظام هذا الخطر منفصلًا. إنفاذ سقف مطلق يستلزم حجزًا ائتمانيًا منفصلًا للطلبات المعلقة وتصميم سياسة جديدة.
8. العملاء خارج التطبيق يستطيع التاجر متابعة ديونهم الأحادية غير المعتمدة؛ لا يمنع الحد تسجيلها قبل وجود علاقة معتمدة، ولا يجوز تسميتها رصيدًا مشتركًا معتمدًا.
9. الإيقاف يحفظ سجل السياسة مع enabled=false ويرفع version، ويسجل التغيير في relationship_credit_limit_events وfin08_audit_events.

## قاعدة البيانات والترحيل

server/sql/004_fin16_credit_limits.sql بعد 001 و002 و003:

- relationship_credit_limits: مفتاح فريد (relationship_id,currency)، الحد numeric(20,4) غير سالب، mode warn/block، enabled، version متزايد، آخر معدل وتوقيت.
- relationship_credit_limit_events: لكل تغيير فعلي في السياسة تاريخ وهوية دون بيانات الهاتف.
- كل فحص سياسة وإنشاء دين جديد يحدث في معاملة PostgreSQL واحدة تحت قفل العلاقة FIN-13؛ تغيير السياسة وتسجيل دين متزامنان بترتيب خادمي واضح.
- لا تغيير في financial_movements أو القيود المعتمدة الحالية.

## REST API

المسار: /v1/relationships/{relationshipId}/credit-limits

**GET** (للتاجر والعميل الموثقين): يعيد scope=approved_ledger_and_separate_unapproved_exposure و3 صفوف عملات، تشمل approved_balance، pending_debts، pending_payments، pending_net_estimate، السياسة وإصدارها، وapproved_exceeds_limit.

**POST** (للتاجر وحده):
- تفعيل تنبيه: {"currency":"YER","enabled":true,"limit_amount":"100000.0000","mode":"warn"}
- تفعيل منع: {"currency":"USD","enabled":true,"limit_amount":"200.0000","mode":"block"}
- الإيقاف: {"currency":"USD","enabled":false}
- تكرار الطلب بالمحتوى نفسه يعيد replayed=true ولا يكرر تغيير السياسة.

**POST /v1/relationships/{id}/operations** للدين الجديد:
- في warn: يعيد credit_warning بنطاقه وقيمه كسلاسل Decimal.
- في block: يرجع HTTP 409 credit_limit_exceeded، دون حفظ دين أو اعتماد مالي.
- **منع التحايل عبر المسار القديم:** POST /v1/merchant/claims يحترم أيضًا سياسة المنع/التنبيه عندما يكون لدى السجل الخاص علاقة نشطة معتمدة. لا يُمنع إعادة تشغيل نفس المطالبة باستخدام مفتاح idempotency الأصلي؛ أما العميل غير المنضم فلا يوجد لديه رصيد مشترك معتمد يخضع للحد.
- الدفعة مسموحة حتى في حالة تجاوز الحد؛ لا تتغير الديون السابقة أو طلبات التعديل تلقائيًا.

## اختبارات القبول

- استقلال حدود YER وSAR وUSD.
- دين معتمد 600 YER ودفعة معتمدة 200 YER ينتجان رصيدًا 400؛ الحد 500 يسمح بدين 100 ويمنع 100.0001.
- الديون المعلقة 150 تظهر منفصلة ولا تدخل معادلة المنع.
- warn SAR=5 يحذر من دين 7.2501؛ بعد موافقة العميل يصبح الرصيد المعتمد 7.2501 مع بيان التجاوز.
- لا تعطل block الدفعات أو الأرصدة الدائنة.
- block تطبق قبل الاعتماد التلقائي، وإيقافها لا يغير أي قيد معتمد.
- ضبط السياسة موثق بالصلاحية وإصدارها لا يعود للصفر بعد إيقافها.

**حدود الإطلاق:** OTP الحقيقي وجلسات Flutter الآمنة، اختبار جهازين، النسخ الاحتياطي والاستعادة، وإشعارات المخاطر الفورية ليست ضمن FIN-16.
